## Correcciones aplicadas

- Se aislaron claves y proveedores en tests; las pruebas legacy ahora habilitan su
  fallback explicitamente. No gastan cuotas por cargar el .env real.
- Cobertura de Groq: schema estricto, redaccion, errores HTTP, 429/cooldown, abort por
  timeout, JSON invalido, respuestas truncadas, observabilidad y prioridad.
- Pruebas de agentes comerciales, consentimiento, ownership, herramientas permitidas,
  permisos, versionado, idempotencia y fallos controlados.
- Matching/Pricing invalidan cache cuando cambia el modelo o la disponibilidad
  configurada de proveedores. Solo se usan indicadores booleanos y nombres de modelo.
- MarketingEditor web incluye campaign.variants en las dependencias del efecto.
- Mobile: Expo 50 -> 54.0.37; React Native 0.81.5, React 19.1.0, Navigation 7,
  Firebase 12.19.0 y paquetes Expo compatibles. Node minimo: 20.19.
- UUID usa expo-crypto en lugar de una dependencia directa de expo-modules-core.
- Se declararon Babel, expo-constants y expo-linking para builds reproducibles.
- Variables publicas movidas a referencias estaticas process.env.EXPO_PUBLIC_*:
  la lectura anterior desde globalThis no se incorporaba al bundle.
- Firebase 10 causaba "Component auth has not been registered yet" en Android.
  Firebase 12 corrigio el arranque, sin deshabilitar las reglas de resolucion de Metro.
- Overrides acotados de postcss y undici redujeron el audit movil de 27 a 16.
  No se uso npm audit fix --force ni se migro a Expo 57.

## Bloqueantes antes de publicar

1. Seguridad movil: resolver o mitigar formalmente las dependencias restantes.
   La alta es image-size 1.2.1 utilizada por Metro al procesar assets. Las otras
   causas son decode-uri-component y uuid, con avisos propagados a sus consumidores.
   No reemplazar image-size por una version mayor a ciegas: Metro usa su API anterior.
2. Sesiones moviles: getAuth sigue sin persistencia nativa de Firebase.
   AuthContext guarda perfil/ID token en SecureStore, pero eso no restaura la sesion
   renovable de Firebase al reiniciar. Implementar y probar persistencia, refresh,
   revocacion, expiracion y cierre de sesion. Se observo el aviso del SDK.
3. Cloudflare: adaptar y desplegar el backend Node/Express/Firebase Admin en la
   modalidad elegida; no asumir que funciona al copiarlo a un Worker.
   Configurar dominios, HTTPS, secretos, CORS y URLs web/mobile/webhooks.
   No hay .github ni pipeline CI/CD en este checkout. La guia conserva Cloud Run
   como referencia historica, no como despliegue acordado ni realizado.
4. Pagos: Mercado Pago no pasa la comprobacion local de configuracion completa.
   Falta BILLING_USD_TO_ARS. Probar checkout, webhook firmado/idempotente,
   renovacion mensual confirmada por proveedor, cancelacion, cambios de plan,
   rechazos, reintegros y conciliacion en sandbox antes de produccion.
5. Infraestructura: publicar/verificar Firestore Rules, Storage Rules e indices;
   preparar backups/restauracion, scheduler productivo, alertas y procedimiento
   de incidentes. Emulator no demuestra que el entorno remoto este configurado.
6. Secretos: rotar las claves compartidas en chat; configurar secretos por entorno.
   Comprobar restricciones de claves publicas y deshabilitar demos en distribucion.
7. Validacion externa: registro/login, flujo Job -> matching -> pricing ->
   seleccion -> coordinacion y estados por rol en staging. No se hizo E2E
   autenticado de extremo a extremo en navegador, Android e iOS.
8. Canales y IA: Resend, WhatsApp y Maps tienen valores de configuracion, pero eso
   no prueba dominio verificado, permisos, entrega o cuotas. Validar cada canal
   que se habilite. Groq respondio; falta evaluar todos los agentes, limites de uso,
   calidad, fallbacks y presupuesto. El modelo configurado figura como Preview.
9. Distribucion movil: builds firmados, dispositivos reales, permisos,
   notificaciones y pruebas de restauracion. El bundle iOS no equivale a probar
   un iPhone. Play/Apple requieren integracion y verificacion real de compras.

## Alcance funcional aun pendiente

Estos puntos no quedan terminados por las pruebas de hoy:
- Reputation completo con reviews verificadas que alimenten Matching.
- Coordinator avanzado: SLA, disputas y recuperacion operativa.
- Cobro real de transaction fee, liquidacion y facturacion fiscal.
- Compras Play/Apple, validacion servidor, notificaciones, restauracion y revocaciones.
- Sales/Marketing: captacion autorizada, canales reales, atribucion y cohortes.
- Memory/RAG: embeddings, indice vectorial, evaluacion e ingesta controlada.
- Orchestrator: cobertura de todos los eventos y gestion uniforme de cancelaciones.
- Observabilidad global: costos, retencion, alertas, presupuestos y runbooks.
- BI: GMV, CAC/LTV, retencion/churn y otros indicadores completos con datos reales.

Se puede definir un MVP mas acotado, dejando estas funciones deshabilitadas y sin
ofrecerlas como completas. Los bloqueantes de seguridad, sesiones, permisos,
despliegue y cobros habilitados siguen aplicando.
